The Master Key is read from disk on startup and held in memory. It is never stored in the database. Every stored Credential is encrypted with it.

Rotation

To rotate the Master Key, you must re-encrypt every stored Credential under the new key. The process is:

{{if .DataDir}}
  1. Back up the current Master Key file
  2. Generate a new key: openssl rand -hex 32 > /tmp/new.key
  3. Stop nagipath
  4. Re-encrypt: nagipath rekey --data={{.DataDir}} --old={{.Path}} --new=/tmp/new.key
  5. Replace the old key: mv /tmp/new.key {{.Path}}
  6. Start nagipath

The re-encryption is one transaction: every Credential moves to the new key or none does. Until step 5 the old key is still the installed one, so a failed run leaves a working installation. Do not delete the old key until nagipath starts with the new one.

{{else}}

This installation reads its Master Key from NAGIPATH_MASTER_KEY, not from a file. nagipath rekey takes two key files, so write the current and the new key to files first, run it with --old and --new, then set the environment variable to the new value and restart.

{{end}}
Security model

Private key material is never rendered and never transferred. A Credential screen shows a fingerprint and a name, never a key. The Master Key is the only secret that can decrypt them, and it is never shown in the UI, never returned by the API, and never included in a diagnostics bundle.
